# Health Tracker JSON v0.2

Telegram-бот на Python/aiogram с хранением данных **без СУБД**. Все измерения, питание, тренировки, часовой пояс и напоминания сохраняются в JSON, по файлу на Telegram user ID: `data/user_<id>.json`.

## Запуск

1. Создать бота через @BotFather.
2. Скопировать `.env.example` в `.env` и указать `BOT_TOKEN`.
3. `docker compose up -d --build`.
4. Написать `/start` боту, затем `/help` для команд.

## Bothost

Развернуть с Dockerfile и переменными `BOT_TOKEN`, `DATA_DIR=/app/data`, `DEFAULT_TIMEZONE=Asia/Yekaterinburg`. **Критически важно**: настроить **постоянное хранилище /app/data**. Без сохраняемого тома данные могут исчезнуть при пересоздании или обновлении контейнера. Уточните, поддерживает ли текущий тариф Bothost такие тома; если нет, нельзя полагаться на локальные JSON для долгого хранения. Создавайте регулярные резервные копии. Запускайте **один экземпляр** бота.

## Возможности

- `/pressure 125 80 72`, `/weight 67.8`, `/pulse 72`, `/metric сахар 5.4`
- `/history`, `/chart weight`, `/chart pressure`, `/chart pulse`
- `/food Гречка; 150; 110; 4; 1; 21` (поля: название; граммы; ккал, Б, Ж, У на 100 г)
- `/foodlog`
- `/workout Ходьба; 40; 150` (калории можно пропустить)
- `/workouts`
- `/remind 09:00; Принять назначенное лекарство`, `/reminders`, `/unremind 3`
- `/timezone Europe/Moscow`, `/export`

Продуктового каталога нет: пользователь вводит КБЖУ на 100 г вручную. Ежедневные напоминания проверяются раз в 20 секунд, когда бот работает. Значения расхода ккал при тренировках вводятся пользователем. Даты записей — текущее время UTC с отображением в пользовательском часовом поясе.

## Надёжность и конфиденциальность

- JSON записывается через атомарную замену файла и с блокировкой на пользователя **внутри одного процесса**.
- Это MVP для небольшой аудитории; JSON не предназначен для параллельных контейнеров, большой нагрузки или сложных поисковых запросов.
- После сбоя при доставке напоминания возможны повторная отправка либо пропуск. При выключенном боте напоминания не отправляются.
- По Telegram ID файлы изолированы логически, но **не зашифрованы на диске**. Ограничьте доступ к файловой системе и к бэкапам. Медицинские данные чувствительны.
- `/export` выгружает личную историю. Регламент удаления данных и восстановление из резервных копий — следующая версия.
- При добавлении Mini App сервер сможет читать эти JSON или выполнить миграцию в БД. Telegram `initData` следует валидировать на сервере.

## Изменения v0.3
- `/menu` — кнопочное меню разделов; `/start` и `/help` тоже показывают кнопки.
- `/today` — суточная сводка по внесённым данным.
- `/week` — сводка последних семи календарных дней в часовом поясе пользователя.
- `/delete ID` — удаление измерения, питания или тренировки по номеру из истории.
- История теперь показывает номера записей `#ID`.
- Формат пользовательских JSON-файлов не изменён: ранее внесённые записи совместимы.

**Внимание:** перед обновлением сохраните резервную копию папки `data/`. Данные сохраняются только при постоянном хранилище, подключённом к `/app/data`. Для работы нужен один экземпляр бота (без параллельных контейнеров).
